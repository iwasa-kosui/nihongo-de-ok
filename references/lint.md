# CLIと静的検査の詳細

## CLI

スキルルートの `scripts/lint.mjs` を実行します。`--type` は必須です。指定できる区分は `design-doc`、`prd`、`adr`、`rfc`、`stock`、`flow`、`record` です。前五つはストック文書用の検査を含み、後二つはそれぞれの区分で検査します。外部の作業ディレクトリから実行するときは、スクリプトと入力ファイルに絶対パスを指定できます。

```sh
node /absolute/path/to/nihongo-de-ok/scripts/lint.mjs \
  --type design-doc /absolute/path/to/design.md
node /absolute/path/to/nihongo-de-ok/scripts/lint.mjs \
  --type flow --format json /absolute/path/to/status.md
```

`--format` は `pretty-error`（既定）または `json` を指定できます。入力ファイルは1つ以上の Markdown ファイルです。未知のオプション、未対応の拡張子、存在しないファイルは引数・設定・入出力のエラーになります。検査は入力ファイルを変更しません。

## 検査するルール

`preset-japanese` は助詞の重複や二重否定など、既存の日本語ルールを検査します。`no-ai-jargon` は直訳調・抽象表現を検出します。`no-opaque-compound` は意味を読み取りにくい造語を検出します。`no-vague-action` は主体・対象・条件が不明確になりやすい限定的な動作表現を検出します。

ストック文書には `stock-boundary` も適用され、作業進捗、チェックボックス、PR・Jira の追跡情報を検出します。`table-cell-length` は全区分に適用され、Markdown の表の見出しと本文セルを検査します。

## 表の文字数

`table-cell-length` は、表示上30文字以上のセルを指摘します。Markdown の装飾記号とリンク先URLは数えず、リンク表示文とインラインコードは数えます。セル前後の空白は数えません。結合文字と複数コードポイントの絵文字は、表示上の1文字として数えます。セル内で改行しても、セル全体で数えます。

引用原文とコード例はこのルールの対象外です。HTML や Markdown 以外の表にも同じ上限を適用し、執筆者が確認します。長い説明を表へ詰め込まず、表の外へ移してください。条件や例外を削ってはいけません。意味のない分割や独自の略語で文字数だけを減らしてもいけません。

## 終了コード

終了コード `0` は指摘がないこと、`1` は指摘があることを示します。`2` は引数、設定、入出力のエラーです。依存関係が未導入など、スクリプト自体を起動できない場合も未検証として扱います。

指摘の置換候補は文意を確認してから直し、最終変更後に再検査してください。検査に通っても、辞書やパターンにない表現、文をまたぐ指示関係、事実の正しさは保証されません。日本語の意味と文書の役割は [日本語の基準](japanese.md) に沿って確認します。一般の技術語を長さだけで禁止しません。

## `allow` 設定

正確な意味を伝えるために必要な用語は、[`.textlintrc.json`](../.textlintrc.json) の該当ルールへ `allow` の文字列として追加できます。既存の `rules` の該当設定だけを変更してください。同梱CLIはスキルルートの設定を読み込みます。例えば次の設定は、「レバレッジ比率」と一致する範囲だけを `no-ai-jargon` の検査対象から外します。

```json
{
  "rules": {
    "no-ai-jargon": { "allow": ["可観測性", "レバレッジ比率", "ロバストな推定"] },
    "no-opaque-compound": { "allow": [] },
    "no-vague-action": { "allow": [] },
    "stock-boundary": { "allow": [] },
    "table-cell-length": true
  }
}
```

同じ設定方法を `no-opaque-compound` と `no-vague-action` にも使えます。理由を確認した用語だけを指定し、検査を通すためにルール全体を無効にしたり、問題文をコード・引用へ移したりしないでください。`allow` は用語の一致範囲だけを除外し、同じ段落の他の表現は検査します。表セルの上限は `allow` で緩められません。

## Jira課題IDの例外

`stock-boundary` は、大文字のキーと番号の組み合わせから Jira 課題IDを推定します。`ADR-001` や `UTF-8` などは除外しますが、任意の仕様IDと課題IDを完全には区別できません。

誤検出を避ける必要がある場合は、`stock-boundary.allow` に例外のID全体または接頭辞を指定できます。この例外を指定しても、追跡URL、進捗、チェックボックスの検出は無効になりません。
